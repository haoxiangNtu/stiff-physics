## 1. 任务定义与总体结构

机器人完成一个四段故事,其中第二段为**纯物理接触求解**(无 teleport、无 pin、无隐藏马达拖拽):

| 段 | 内容 | 实现方式 |
|---|---|---|
| 一 | 从静止走到柜前站定 | gait_traj.npz 步态运动学回放(FK),柜子+已落定玩偶从第 0 帧就渲染 |
| 二 | 右手舀取玩偶→拖过桌沿→玩偶自落入半开抽屉→右手撤回→左手推关抽屉(玩偶关入)→双臂归位 | **Stiff-GIPC 全物理仿真**(见 §3-§6) |
| 三 | 手臂不动,倒放步态后退数步离开桌子 | 步态帧 178→110 倒放,非腿关节清零 |
| 四 | 在后退位转身摆臂走开 | 步态帧 259→418 回放,基座平移补偿(bp[110]−bp[259]),手臂按对侧腿相位摆动 |

段间衔接:画面**定格**(仿真/动画不步进),镜头按 smoothstep 在 16-22 帧内滑移到下一机位——共三处(1→2、2→3、3→4)。

## 2. 物理场景(stage2_scene.py)

- **机器人**:`fd_dual_arm.urdf`(40 links / 39 joints,腰部固定于 WAIST=(2.3313, 0.0359, 1.05),yaw −5.83° 烘入 URDF)。**只有双手(掌+指节,水密低模)是真实碰撞体**;手臂/躯干等为盒代理且被排除出碰撞,视觉由全清网格贴皮(§7)。
- **柜子**:程序化 6 盒装配(顶板/底座/双侧/背板/腔上沿),Fixed ABD。桌面高 `CAB_TOP=0.95`。**柜前脸距腰 `FD_CAB_FRONT=0.48`**(原 0.32;为了给左手留出身体净空外移了 16cm,这是消除"左手视觉穿身"的关键,见 §6.3)。
- **抽屉**:8 盒 Free ABD(底/双侧/背/前板/**加长把手**——杆离前板 6.5cm 悬空,给手指留 5.4cm 钩入间隙)。
  - **建成即半开**:prismatic 关节零点=半开,限位 ±0.12(+0.12 全开,−0.12 关死);
  - **完全被动**:`set_prismatic_strength(pj, 0.0)`,无回位弹簧,推到哪停到哪;
  - 密度 300,重力关闭(导轨模式,防下垂)。
- **玩偶**:Toy00.obj 经 fTetWild 四面体化(483 顶点,~1k tets),FEM,`FD_YOUNG=1e5`、`FD_DENSITY=150`(约 30g)、`FD_TSCALE=1`(实际约 6×10×6cm,**手掌大小**——见 §8.1 的重要教训)。出生点 `FD_DOLL_SPOT="2.836,-0.196"`(柜面靠前沿,密度 150 的球落地不滚,落哪待哪)。
- **碰撞白名单**(其余全部互斥):
  - 双手 ↔ 玩偶;右手 ↔ 柜体(桌面可依托);**只有左手 ↔ 抽屉**(右手全程不许碰抽屉);
  - 玩偶 ↔ 柜体/抽屉/地面;
  - 其它两两组合全部 `add_collision_exclusion`,非玩偶体跳过地面碰撞。
- **关节强度**:`FD_JSR=300`(手指曾在抓取中脱臼,从 100 提到 300 解决)、右手手指马达 ×12(`FD_FSTR=12`)。
- Config:dt=0.01,newton_iter_cap=100,velocity_damping=0.3,friction_rate=1.0。

## 3. 核心方法论:人类示范 + 关键帧回放 + 运行时伺服

### 3.1 人类示范(pose_bench.py)
交互式遥操作 UI:每臂 7 滑条(r5/l5=腕滚)、掌心 IK 面板(XYZ 目标,固定腕解 r1-r4)、右手 grasp 滑条、拇指 root/curl 独立滑条、左手食指/其余三指分离。用户在真实引擎里亲手演示,按 REC 存关键姿态到 `user_poses.json`(31 条)。最终采用:

| 条目 | 内容 |
|---|---|
| #27 | 到位开手姿态(腕滚 35.5°,四指张开) |
| #28 | **抓持姿态**(腕滚 65.8°、grasp 0.159、拇指 root −1.2 / curl −0.8)——#27→#28 的差分就是"沉肩+滚腕+合指+拇指成袋"的**舀取微动作** |
| #30 | 提起姿态(肘 −88.2°,grasp 0.278) |
| #18-23 | 左手推关抽屉的路点序列 |

### 3.2 时间线构建(stage2_user_timeline.py,最终 v19)
30 个关键行 `(t, 双臂关节角, 手指字段)`,构建期工作:

1. **柜距偏移烘焙**:`SHIFT = FD_CAB_FRONT − 0.32`,用**全 7 关节 IK(位置项 + 0.05×姿态 Frobenius 罚 + 关节正则)**把 #27/#28 的掌位平移 SHIFT 而**腕姿态几乎不变**(0.48 时位置误差 2.1cm、姿态误差 0.015)。这是"用户示范在新几何下依然有效"的关键。
2. **途经点 IK**(`ikw`:r1-r4 求解、腕 r5-r7 钉死在示范值):
   - 右臂:`SIDE1`(体右侧 2.37,−0.43,1.06)→ `SIDE2`(桌右上方 2.69,−0.40,1.22)→ `ABOVE`(玩偶正上方)→ 垂降;返程 `UPRIGHT`(右上方)→ SIDE2 → SIDE1 → 垂臂。**全程从右侧绕行,不跨越桌面**。
   - 左臂:`L_SIDE1`(体左侧 2.47,+0.48,1.05)→ `L_SIDE2`(2.46,+0.32,0.99,已按躯干凸包外推)→ 伺服接管;返程原路。
   - 拖拽键:`DRAG1 = p_hold − F·0.05 + L·0.03`、`DRAG2 = p_hold − F·0.065 + L·0.03`(**贴桌面高度**,+3cm 左偏让落点偏向抽屉 bay 中心)。
3. **限速重排**:相邻行按 `max(名义时长, 最大关节差/0.45 rad/s, 手指差/0.9)` 重排时刻(大摆臂会让 Newton 迭代爆炸,限速后单步迭代从 90+ 降到 ~20)。
4. 里程碑检查表(`check_spec`)与两个伺服的行号元数据写入 json。

### 3.3 运行时双伺服(stage2_user_run.py)
开环回放对半混沌的软体/抽屉状态不鲁棒,两个**测量-重瞄**伺服解决:

- **伺服 1(右手,合指前发射)**:从引擎顶点实测玩偶"桌面凸起"(z>0.962 区域顶部 6cm 均值),与期望球位比较得漂移 `(dx,dy)`(>12cm 拒动并报警);对抓取相关行做**全 7 关节位置+姿态 IK 平移**(典型误差:位置 0.0-0.2cm、姿态 0.001-0.015),随后**从该行起重新限速排时**并按 `check_spec` 重算里程碑时刻。
- **伺服 2(左手,出发前发射)**:由实测 `pull` 反算把手世界位置 `hp`;生成 5 个目标:高位远点(hp−F·0.13+L·0.05,z 1.005)→ **远处降到杆高**(同 xy,z 0.865;指尖离杆 5cm 才降,杜绝下降勾杆)→ 斜滑入(hp−F·0.075+L·0.02)→ 贴杆(hp+F·0.02)→ **实测推关终点(hp+F·(pull+0.175),推过硬限位)**;逐个 ik_l(腕钉 #23 示范值)写入行,dwell 行复制推关解(防回弹),撤回行复制降杆解;重排时。

### 3.4 释放的两步拆分(v19,消除"弹飞")
- 行 11:**只开四指**(grasp −0.05 轻微反张),**拇指冻结**在抓持值(root −1.2 / curl −0.8)→ 玩偶靠重力温和滑出,落入正下方抽屉;
- 行 12(+1.2s,玩偶已落底):拇指再走原轨迹(−0.5 / +0.3)→ 行 13 右臂右上方撤离。
- 历史对照:四指+拇指同时张开会把 30g 玩偶抽飞到 40cm 外(甚至挂在指笼上被整只手带走)。

## 4. 里程碑自检与看门狗

- **里程碑**(执行器内自动判定+截图):
  - M3 玩偶入抽屉:质心在 bay 中心 ±(0.32/0.38) 且 0.70<z<1.12 且相对落定位移 >4cm;
  - M4 抽屉关死:pull < −0.09(定稿轮 −0.134,玩偶随抽屉进入柜体);
  - M5 归位:双掌位置判定(palm z<0.95 且 x<2.52)。**不要**用 `get_revolute_current_angles()+rj` 索引判(实测读错关节,视觉归位仍报 1.57)。

## 5. 构建期验证(每次改动后、发射仿真前必跑)

1. **避桌扫掠**:0.1s 采样整条时间线 FK,双掌+指尖近似探针不得进入柜体体积(前脸起 0.62m 纵深、±0.40 侧向、z<0.955);
2. **bay 禁入**:探针不得进入抽屉敞开腔(右手拖拽窗口、左手推关窗口豁免);
3. **躯干凸包**:轴心 (2.3313,0.0359)、半径 0.15m(躯干半深 ~0.12 + 3cm 余量)、z 0.55-1.38 的圆柱禁区;非垂臂时段的掌+四向探针不得进入(左手作业窗口实测 17-48cm);
4. **可达性**:所有 IK 目标打印误差,抓取键 >3cm 或姿态 >0.03 就要重新设计目标(0.48 柜距是可达上限:0.52 时误差升到 4-5cm 被否决)。

## 6. 探索史:哪些路走不通,为什么(按时间序)

### 6.1 "提起搬运"不可复现 → 改"拖入"
用户示范的 #28→#30 在其交互会话中确实把玩偶提到 z=1.009,但**开环回放毫米级对准(位置 0.2cm、姿态 0.012)仍 5 轮全部滑脱**——FD 手平板掌+浅捏(0.159)对硬面矮软物的竖直约束不足,示范中的提起是交互瞬态。**方案 B:舀住→贴桌拖过前沿→自由落体进正下方半开抽屉**,拖拽有摩擦水平分量天然可行(此前实测能拖 3-15cm),之后 M3 十余轮连续 PASS。**落点混沌控制**:+3cm 左偏防骑侧壁;拖到刚过沿即停(过头 3.5cm 就会飞越 bay 骑上前板);贴桌面高度拖(抬高 3cm 玩偶会整只挂在指笼里被带走)。

### 6.2 撤回路径三次死锁教训
1. 释放后从"桌面上方"的键横撤 → 前臂压上桌沿,IPC 接触死锁,**Newton 每步打满、整个世界冻结**(玩偶/左臂/抽屉全部静止,M4/M5 连锁全挂);
2. 压实(tamp)后低位横拉 → 指尖以 z≈0.9 耙过 bay,勾住玩偶连抽屉整个拽出限位(pull +0.205);
3. 修法定式:**接触作业结束后先垂直升高,再走高位绕行**;任何键不得让指尖低于桌面(掌高 ≥1.03)。
4. 左手同理:从把手上方降落必勾杆(+2~4cm 随机),小臂还会掉进抽屉箱卡死 → **远处降到杆高再水平滑入**。

### 6.3 视觉穿身问题(两轮根治)
半开抽屉加长把手距腰仅 12cm,任何左手前伸都会与躯干视觉重叠。**柜子(连抽屉/玩偶)整体外移**是唯一解:0.32→0.44→0.48(共 16cm;20cm 超可达被否)。配套:示范姿态全姿态 IK 烘偏移(§3.2)、左偏斜滑入、L_SIDE2 凸包外推、双侧绕行(右臂也一样:垂直起臂改为**先向体侧摆出再从桌侧面绕入**,应用户点评加入)。

### 6.4 引擎级陷阱(踩过的坑,已存项目记忆)
- **metis 排序缓存劫持**:`load_mesh_from_data`(FEM+preconditioner)把网格写 `/tmp/stiffgipc_mesh_data/tmp_mesh_<N>.msh` 再经 metis 缓存(`Assets/sorted_mesh/`),缓存**只按文件名+顶点数校验**——改 FD_TSCALE 顶点数不变,**静默加载旧坐标**(transform 却按新几何算 → 物体"正确位置错误尺寸")。这导致"玩偶放大"请求从未生效、诊断绕了十几轮。修复:怀疑网格不对时 `rm -f Assets/sorted_mesh/tmp_mesh_*`;验证尺寸永远用引擎内 `get_vertices()` 实测。
- `teleport_fem_vertices` 在活跃接触中调用 → CUDA invalid argument 崩溃;FEM pin 只能 finalize 前建。
- GPU 轮间非确定性 ±1-2cm(原子归约顺序)——一切"绝对坐标回放"都要配伺服。
- 抽屉 prismatic 限位是 penalty 软限位,可以被推过(利用它做"推过头关严",也要防被拽出)。

## 7. 渲染合成(composite_render.py)

- **阶段二贴皮**:引擎里手臂/手是低模代理;渲染时对每个 link 从 npz 顶点子集(每 link 采样 48 点)做 **Kabsch 刚性配准** 得世界变换,套在全清 URDF 网格上;躯干/腿/头冻结在步态第 178 帧 FK 姿态。玩偶/柜子/抽屉直接用引擎逐帧顶点(纯物理,无任何脚本层)。
- **家具时序**:阶段一用"玩偶落定态"(npz t=2.0 帧)静态渲染(不播下落);阶段二从落定帧起播;阶段三/四用终态(抽屉关死、玩偶在内)。
- **镜头**:阶段一静态全景(行走路径+柜子同框);阶段二右侧剖面位;阶段三/四跟拍;三处段间 smoothstep 定格渐变。
- 编码:`ffmpeg -r 25 -i f%05d.png -c:v libx264 -pix_fmt yuv420p -crf 18`。

## 7.5 USD 导出(export_usd2.py)

- **帧程序与合成器共用同一状态机**(生成器 `frame_program()` 逐帧产出 链接变换/家具顶点/相机),保证 USD 与 mp4 帧对齐;
- lite 版:`fast_simplification` 每 link 减面 96%(670 万→27 万顶点),`xformOp:transform` 逐帧时间采样 **且写默认值**(只读默认值的导入器也能看到正确姿态——这是"查看器里机器人消失"的第一性修复);
- flat 版:减面 98.5%,每帧把 link 顶点变换到**世界空间直接写 `points` 时间采样**,无任何 xform——Houdini 等对变换动画支持参差的管线保证可用(玩偶/家具本来就是这种机制,所以它们从来显示正常);
- 相机:由 eye/at(+Z up)构造行向量矩阵写 `/World/Cam`,焦距 18.5mm ≈ 45° 垂直视场。
- 教训:**670 万顶点是多数 DCC 导入器的隐性上限**,交付 USD 一律先减面。
