对照 Alloy：方法与实测

Alloy 是 Argon Robotics 在 11 月 11 日开源的机器人学习物理引擎（Apache-2.0，pip install alloy-engine）。 我们按它的说明装在自己的 A800 上，读了它的源码确认它到底用什么方法，再把同样的六个场景放进 Alloy 和 StiffGIPC 里各跑一遍，用同一个渲染器出并排视频。 结论：Alloy 不是一个新的求解器，而是把 Newton 和 MuJoCo Warp 两套现成引擎内嵌、再加一个自写 SPH 液体求解器的“编排层”，各求解器分开算、定时交换数据； 接触用罚函数或软约束，没有无穿透保证。在高速球打板、小球压薄片、两指夹泡沫三组里，Alloy 的物体穿进或穿过了对方，我们三组都没有穿透。 它的长处是速度和并行：单个场景的布料快约 3 倍，一张卡上同时跑上千个场景。另一方面，杯中水这组暴露了我们自己的问题：小容器里我们的水面偏高 13–19 %。

二、Alloy 用的方法（读源码确认）

我们读的是 GitHub 上的源码（提交 575bf94，与 PyPI 上的 0.1.2 对应），下面每一条都在代码里找到了对应位置。

Alloy 0.1.2StiffGIPC
整体结构内嵌 Newton（NVIDIA / DeepMind 等的开源引擎，1.8 版加 12 个自己的提交）和 MuJoCo Warp 3.17，按物体自动选求解器；各求解器分开算，每 1.25 ms 通过“代理体”交换一次位置和动量（交错迭代加松弛，或线性化 ADMM）一个整体的隐式求解：刚体、关节、布 / 壳、软体、液体在同一个能量最小化（牛顿法）里一起算
刚体、机器人MuJoCo Warp：软约束接触（允许一定穿透）、牛顿法、单精度；刚体步 1.25 ms；没有连续碰撞检测仿射体（ABD）加关节约束，双精度
布、软体Newton 的 VBD（顶点块下降）：每步固定迭代 40 次，没有收敛判据；布与刚体只在顶点上检测接触（每个顶点当成一个小球），三角面不参与有限元壳 / 四面体，按容差收敛；点–三角、边–边都参与接触
接触罚函数 / 软约束；布的自接触另有“分离平面 + 每步位移上限”的截断（因此带自接触的布最快只能约 3 m/s）IPC 障碍函数（距离趋于 0 时能量趋于无穷）+ 连续碰撞检测的线搜索：构造上不穿透
液体自写的 DFSPH（一种无散 SPH），粒子 4 mm（“super” 档 2 mm）；容器壁用距离场；实体壁最薄 1.25 mm，更薄的拒绝建模；默认没有表面张力MPM（网格加粒子），与固体在同一个牛顿求解里耦合；薄壁两侧分开处理；有表面张力
沙、膏体Newton 的隐式 MPM（Drucker–Prager 屈服面）没有颗粒材料
并行一个模型里复制成百上千个场景，GPU 上批量算单个场景为主
出错时每个场景有健康评级；判为无效的场景退回上一个正常状态并冻结，不纠正求解本身保证不穿透；初始就穿透的场景直接报错

Alloy 自己的文档把这些限制写得很清楚：它的“已知问题”页列了 90 条，例如快速小物体会穿过薄板、 比布的网格小的物体会从布里穿过。下面的实测就是照着这些页面的场景做的。

水深误差 = 按水面实测的深度相对于“体积 ÷ 杯底面积”。我们这边的问题：贴着杯壁和杯底 2–4 mm 的粒子层偏稀（最底下 2 mm 只有应有粒子数的 64 %），所以水面偏高； 网格加密到 2 mm 仍偏高 14 %，不是分辨率问题；换成引擎默认设置则反过来，底层粒子堆积、水面偏低 6 %。在 55 mm 宽、300 mm 高的水瓶里这个影响很小（见水瓶修复）， 但在烧杯、试管、滴管这样的小容器里会明显，这是我们接下来要查的。

单个场景 Alloy 快约 3 倍；并行到 256 个以上时，它每秒能算约 2.6 个场景秒，相当于我们单个场景的 70 倍左右。这是它做强化学习的主要优势。 哪一边的下垂更接近真实的布需要实验，Alloy 自己的已知问题页列了几条默认迭代次数下布偏软或偏硬的情况。

九、我们的问题与可借鉴之处

  • 小容器里的液体体积（第七节）：贴壁、贴底的粒子层偏稀，水面偏高 13–19 %。要查清原因并修。
  • 速度和并行：同样的布料单场景慢约 3 倍；没有“一个模型里复制上千个场景”的批量模式。
  • 可借鉴：Alloy 每个场景都有健康评级，每条报错都带修改建议，已知问题逐条写清楚量级和绕开的办法，还给编程智能体准备了文档和工具接口。这些工程化的东西值得用到我们的发布版里。

十、测试条件

  • Alloy：PyPI 上的 alloy-engine 0.1.2（11 月 12 日发布），装在独立的 Python 3.12 环境里；源码对照 GitHub 提交 575bf94。StiffGIPC：开发分支当前构建。
  • 硬件：一张 NVIDIA A800 80 GB，驱动 535（CUDA 12.2）。Alloy 文档要求驱动 580 以上，所以做了两处改动：
    • 用 NVIDIA 官方发布的 CUDA 12 版 Warp 1.18.0（校验和与官方一致），并关闭它的 MathDx 编译路径；
    • 这个驱动不支持 CUDA Graph 的条件节点，所以含液体的场景关掉了 Alloy 的 CUDA Graph；纯布料和刚体场景开着。
    物理结果不受影响：Alloy 文档里的例子我们逐个对上了数值（落球最低 0.427 m、杯中水 512 粒 33 ml 全在杯内、布下垂 0.184 m、方块半埋地下判为无效）。速度是 Alloy 的下限，驱动 580 以上的机器上会更快，尤其含液体的场景。
  • 两边的场景尺寸、材料参数、控制步长对齐（具体见各节）；每个场景各跑一次。视频两边用同一个渲染器、同一机位和颜色。
  • Alloy 里有两组跑得很慢没有完成：棉布上的 2 g 自由小球、铝片顶点正上方的 2 g 自由小球（分别 35 和 25 分钟没算完 1 s）。
  • 没有对比：机器人抓布、倒水等带机器人的场景；沙和膏体（我们没有颗粒材料）。
