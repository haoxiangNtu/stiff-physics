# 关于这套手册(公开仓读者请先读这一页)

这套手册原本写给引擎开发者,现同步到公开仓供 wheel 用户使用。有三件事需要先说明,
否则你会在阅读时踩到预期落差。

## 1. 这个仓库不含引擎源码

手册里大量陈述带着 `文件:行号` 出处(例如 `stiff_physics/engine.py:455`、
`StiffGIPC/gipc_modules/09_friction_sets_host_mem.inl:597`)。**这些路径指向的是
私有工程仓的源码树,本仓库没有这些文件**。出处保留在文中是为了让引擎维护者能一键
定位,也让每条陈述都可被追责——对 wheel 用户来说,把它当作"该结论有据可查"的标记
即可,不必去找文件。

Python 侧的路径(`stiff_physics/*.py`)例外:它们随 wheel 一起安装,
`pip show -f stiff-physics` 可以定位到你环境里的实际文件。

## 2. 你装的 wheel 属于"稳定线"

手册覆盖两条产品线,每个 API 和特性都带适用线标注:

| 标注 | 对 wheel 用户的含义 |
|---|---|
| 【稳定线+phase-cd】 | **你有** |
| 【仅稳定线】 | **你有** |
| 【仅 phase-cd】 | **你没有**——这是未发布的工程线特性(整帧 CUDA Graph、GPU 驻留 RL、episode 回放、checkpoint v2 等) |
| 【实验性,默认关】 | 视其适用线而定,且默认关闭、不承诺稳定契约 |

看到【仅 phase-cd】的章节可以跳过,除非你打算从源码构建工程线。

## 3. 最新 wheel 是 v0.8.5.4,它改变了摩擦行为

手册的行号基线是 v0.8.5.3,但**发布的最新 wheel 是 v0.8.5.4**,它把两个摩擦默认值
改成了开启:

- `Config.absolute_epsv = 1e-4`(m/s)——静摩擦阈值不再随场景尺度派生
- `Config.friction_anchor = True`——摩擦锚点跨步持久(真静摩擦)

**这会改变所有含摩擦场景的轨迹。** 好处是长时保持抓取不再蠕变(实测保持段滑移
3.7 mm → 0.00 mm),代价是 step 时间约 +9%,且**任何既有轨迹/回放结果都不再逐位复现**。
需要旧行为时两个参数都要关(或用环境变量 `STIFF_EPSV=0` / `STIFF_FRIC_ANCHOR=0`)。

机制详见 [PRINCIPLES_CONTACT.md](PRINCIPLES_CONTACT.md) §4.7,参数说明见
[API_CORE.md](API_CORE.md) §2.1。

## 4. 手册的可靠性是怎么保证的

每份文档在成稿后都经过两轮独立的对抗式事实核查:核查代理被要求**必须在源码中找到
反证**才能提出问题,修订代理再逐条复核后才动笔。该过程记录了 92 条被抓出并修正的
事实性缺陷(计数错误、单位陷阱、版本归属、机制描述、引用失效),完整台账
`docs/manual/AUDIT_LEDGER.md` 保留在工程仓。

手册中仍有未核实的条目,统一登记在 [OPEN_POINTS.md](OPEN_POINTS.md)(编号 OP-xxx,
附验证方法)。发现错误欢迎提 issue,请引用条目编号或 `文件:行号`。
